# DisasterSim — 曖昧な現場の声から避難経路を再計算する AI シミュレーター

**架空の街を使った技術デモです。実際の避難判断には使用しないでください。** 実在のハザードマップ、通行止め情報、人の移動、バリアフリー情報などは一切使っていません。

## できること

1. 地図上に避難所・現在地・危険度（ヒートマップ）を表示
2. 「駅前がかなり浸水してる」「橋は通れなさそう」「西側の道は大丈夫そう」などを文章で入力
3. **Nosana の LLM** が報告を JSON に構造化
   - 対象エリア / 危険の種類 / 危険スコア(0〜1) / 通行不可の可能性 / 解釈の不確実性 / 元の入力文 / 解釈の根拠
4. 解釈結果を表で **確認・修正**（エリアや数値の変更、行ごとの反映 ON/OFF）
5. 確定した情報をグリッドに反映し、**Daytona サンドボックス内で経路探索を再実行**
6. 地図で **更新前後の経路** と **リスク変化** を比較
7. 追加の報告を何度でも積み重ねて更新（報告の削除・リセットも可能）
8. 実在の地図（OpenStreetMap）を背景に表示。「📍 現在地を取得」でブラウザの位置情報を使い、
   **あなたの現在地 = シミュレーション上の現在地** になるように架空の街（1マス≈60m）を重ねます。
   背景地図と現在地以外（危険度・川・避難所）はすべて架空です。
   位置情報は Daytona・Nosana には送信しません。
9. **実在の道路に沿った避難経路**（`road_engine.py`）: 現在地周辺 約1km四方の歩行可能な道路を
   OpenStreetMap の Overpass API から取得し、報告された災害エリアと仮想リスクを避けて経路を探索します。
   比較用に「災害を考慮しない最短経路」も表示し、どれだけ迂回して危険を避けたかを示します。
   - 危険度88%以上の場所を通る道は通行不可（現在地がその中にある場合は抜け出す方向のみ可）
   - 架空の川は実在の橋と位置が合わないため、道路モードでは「通れない線」ではなく高リスク帯として扱います
   - 道路データは1時間キャッシュ。取得に失敗した場合はエラーを表示し、マス目上の経路に切り替えます
   - 道路経路の計算は現在ローカル実行です（Daytona で実行しているのはマス目のシミュレーション）

## 起動

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
export DAYTONA_API_KEY=...           # 任意
export NOSANA_API_KEY=...            # 任意
streamlit run app.py
```

| 環境変数 | 用途 |
|---|---|
| `DAYTONA_API_KEY` | Daytona サンドボックスで経路計算（Python SDK。CLI は不要） |
| `NOSANA_API_KEY` | Nosana LLM による報告の解釈と結果の説明 |
| `NOSANA_MODEL` | 使うモデル ID（未指定なら利用可能な先頭のモデル） |
| `NOSANA_BASE_URL` | 推論エンドポイント（既定 `https://inference.nosana.com/v1`） |

### ローカルデモとスポンサー実接続の区別

画面上に、各結果がどちらで作られたかを常に表示します。

| 表示 | 意味 |
|---|---|
| ✅ Nosana LLMで解釈 | 実際に Nosana の LLM が解釈した結果（生の応答も確認可能） |
| 💻 ローカル簡易ルールで解釈（AIではない） | キーワードルールによる代替。キー未設定時の画面確認用 |
| ✅ Daytona sandboxで実行 | Daytona のサンドボックスで計算した結果 |
| 💻 ローカル実行 / ⚠️ ローカル代替 | 手元で計算。Daytona エラー時はエラー内容も表示 |

API 接続に失敗したときは成功を装わず、エラーをそのまま表示します。**審査デモでスポンサー連携を主張するのは ✅ 表示が出たときだけにしてください。**

## 仕組み

```
文章入力 ─▶ interpreter.py / sponsors.nosana_interpret ─▶ 危険情報JSON
                                                         │ (UIで確認・修正)
                                                         ▼
          sponsors.run_daytona ─▶ sim_engine.simulate(rain, start, hazards)
                                    ├ risk_grid      : 架空の地形リスク
                                    ├ apply_hazards  : 報告をグリッドに重ねる
                                    └ pathfind       : 危険度で重み付けしたDijkstra
```

- `sim_engine.py` — 標準ライブラリのみ。同じファイルを Daytona サンドボックスへ送って実行します。
  - 街には東西に川があり、**西の橋・中央橋・東の橋** でしか渡れません。
  - 報告の反映: 不確実性が低いほど報告値に強く寄せます。通行不可の可能性が高い報告はそのエリアを通行不可にします。
  - 特定エリアの通行止めは、より曖昧な広域の「大丈夫そう」では解除されず、同じエリアへの新しい報告でのみ更新されます。
  - 現在地自体が通行不可エリアにある場合は「そのエリアから抜け出す」経路のみ許可し、警告を表示します。
- `interpreter.py` — LLM 用プロンプト、JSON 抽出・検証（エリア名の補正、値の 0〜1 クランプ）、ローカル簡易ルール。
- `sponsors.py` — Daytona（`Daytona().create()` → `sandbox.process.code_run()` → `delete()`）と Nosana（OpenAI 互換 API）。
- `app.py` — Streamlit UI。

## ピッチ（30秒）

> 災害現場の情報は「この道めっちゃ浸水してる」「橋が危なそう」のように曖昧です。DisasterSim は、そうした人の言葉を Nosana 上の LLM がその場で数値化し、Daytona のサンドボックスで避難経路を再計算します。情報が増えるたびに経路が変わり、その前後を地図で比べられます。今日は架空の街のデモで、実際の避難指示ではありません。
